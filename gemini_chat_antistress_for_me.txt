1. Как устроен классический RAG

RAG — это не отдельная сверхсложная нейросеть, а связка из двух стандартных инструментов:

Модель эмбеддингов (любая): берет текст учебника и переводит его в векторные числа. Сюда подходит абсолютно любая модель: Gemini Text Embedding, OpenAI text-embedding-3-small или даже бесплатная легковесная опенсорсная модель вроде bge-m3 / all-MiniLM-L6-v2.

Основная языковая модель (LLM): любая модель (например, Gemini 1.5 / 2.0 Flash), которая читает найденный кусочек текста и формирует ответ с 3 развилками мысли для ученика.  
MD

Переводить текст в векторные числа (векторизовать) умеет любая эмбеддинг-модель, а не только Gemini.

Генеративные текстовые модели (ChatGPT, Claude, Gemini Flash) генерируют текст, а для превращения слов в массивы чисел ([0.024, -0.158, 0.891, ...]) используются специализированные модели эмбеддингов.

Кто умеет создавать векторы:

Open-Source (бесплатно, без API-ключей, прямо в Python):

Библиотека sentence-transformers с моделями all-MiniLM-L6-v2 или bge-m3. Работает локально на компьютере за миллисекунды.

Google API:

Модели семейства text-embedding-004 (Gemini Embeddings).

OpenAI API:

Модели text-embedding-3-small / text-embedding-3-large.

Cohere API:

Модель embed-multilingual-v3.0 (отлично понимает казахский и русский языки).

Как физически выглядит создание вектора (всего 3 строки на Python):

Python
from sentence_transformers import SentenceTransformer

# 1. Загружаем любую бесплатную модель векторизации
model = SentenceTransformer('all-MiniLM-L6-v2')

# 2. Передаем правило из учебника 9 класса
text = "Квадратное неравенство ax^2 + bx + c <= 0 решается методом интервалов через нахождение корней."

# 3. Получаем готовый массив векторных чисел (числовой отпечаток)
vector = model.encode(text)

print(len(vector))  # Длина вектора (например, 384 числа)
print(vector[:5])   # Первые 5 чисел: [0.0412, -0.0891, 0.1204, ...]
Когда ученик отправляет решение или вопрос, его текст точно так же превращается в числа через ту же модель, а программа математически сравнивает два набора чисел и находит самый подходящий фрагмент учебника.

В NotebookLM (Google Notebook) секрет кроется не в магии эмбеддингов, а в том, что он работает совершенно иначе, чем классический «школьный» RAG.

1. Он не режет текст на мелкие кусочки (Long Context)
В классическом RAG документ дробят на крошечные куски по 300–500 слов, превращают в векторы и скармливают модели только 3–5 найденных кусочков. Из-за этого модель часто теряет контекст всей книги.

NotebookLM работает на базе моделей Gemini с контекстным окном до 1–2 млн токенов:

50 загруженных документов и книг целиком помещаются в рабочую память нейросети.

Модель «видит» весь массив данных разом, связывая факты из начала первой книги с выводом из конца пятой.

2. Технология Context Caching (Кэширование контекста)
Чтобы не гонять миллион токенов через сеть при каждом вопросе пользователя и не упираться в лимиты:

Ваши файлы загружаются и векторизуются/токенизируются один раз.

Google «замораживает» это состояние прямо в оперативной памяти своих серверов (TPU).

Каждый новый вопрос обращается к уже готовому кэшу в памяти — без повторной обработки, с околонулевой задержкой и без расхода квот на повторные эмбеддинги.

3. Почему у обычного API жесткие лимиты и как их обойти
Публичный бесплатный API Gemini Embeddings ставит лимиты на количество запросов в минуту (RPM/TPM), чтобы не перегружать сервера Google.

Для вашего хакатона есть два простых инженерных пути вообще забыть про эти ограничения:

Путь А: Бесплатные локальные эмбеддинги (sentence-transformers)

Библиотека на Python (all-MiniLM-L6-v2 или bge-m3) запускается прямо на вашем компьютере/сервере. У неё нет никаких лимитов и квот — вы можете векторизовать хоть 10 000 страниц за секунды без API-ключей.

Рабочий пример на Python (как в NotebookLM):

Python
import os
from google import genai
from google.genai import types

client = genai.Client(api_key=os.environ.get("GEMINI_API_KEY"))

# 1. Загружаем учебник 9 класса (загружается один раз!)
book_file = client.files.upload(file="algebra_9_kazakhstan.pdf")

# 2. Системный промпт Сократического «Аға»
system_instruction = """
Ты — AI-наставник по алгебре 9 класса. 
Отвечай СТРОГО по загруженному учебнику. 
Если ученик ошибся, не давай готовый ответ. Верни JSON:
{
  "is_correct": false,
  "error_step": "где ошибка",
  "socratic_hint": "наводящая подсказка",
  "thought_forks": ["вариант 1", "вариант 2", "вариант 3"]
}
"""

# 3. Анализ решения ученика с опорой на весь учебник
response = client.models.generate_content(
    model="gemini-2.5-flash",
    contents=[
        book_file,  # Ссылка на учебник (как в NotebookLM)
        "Ученик решает x^2 - x - 6 <= 0 и пишет: корни x=3, x=-2, значит ответ x >= 3."
    ],
    config=types.GenerateContentConfig(
        system_instruction=system_instruction,
        response_mime_type="application/json"
    )
)

print(response.text)

а как понять что развилки хватит

Развилки заканчиваются ровно тогда, когда устранена ключевая слепая зона и ученик готов сделать финальный шаг сам, либо когда сработал защитный лимит глубины.

В коде и педагогической логике это определяется тремя четкими триггерами:

1. Выход на финальный ответ (Eureka Trigger)

Как работает: Развилка помогла понять принцип → ученик вводит правильный ответ или выбирает верный вариант в тренажере.  
MD

Что происходит в системе: Gemini возвращает is_correct: true → развилки мгновенно скрываются → анимация конфетти, начисление +15 ELO, стрик зафиксирован, ячейка у учителя зеленеет (🔴 → 🟢).  
MD

2. Жесткий лимит глубины (Правило 2–3 кликов)

Как работает: В формате 3-минутного фокуса нельзя гонять ученика по бесконечному лабиринту подсказок. Максимальная глубина ветвления — 2, максимум 3 шага.  
MD

Защита от зацикливания (Anti-Stuck): Если ученик 2 раза подряд выбрал неверную развилку-ловушку, ИИ больше не генерирует новые кнопки, а выдает короткую прямую опору: «Ты запутался в знаках. Давай шаг за шагом: корни уравнения x=3 и x=−2. Подставь число 0 в формулу и запиши получившийся знак».

3. Закрытие конкретной подзадачи (Scaffolding)

Как работает: Большинство задач делятся на этапы (Этап 1: найти корни → Этап 2: расставить интервалы).

Снятие развилок: Развилка нужна только чтобы столкнуть мысль с мертвой точки. Как только ученик нажал правильную кнопку этапа (например, [Корни: 3 и -2]), блок развилок исчезает, и фокус возвращается в стандартное поле ввода с кнопкой SEND для завершения задачи.  
MD

Как это реализуется в JSON-ответе от Gemini:

Модель сама отдает статус готовности, управляя интерфейсом:

JSON
{
  "is_correct": false,
  "requires_fork": true,        // true = показать 3 кнопки; false = развилок хватит, ждем ввод ответа
  "fork_step": 1,               // текущий шаг (если step >= 2, прекращаем дробить)
  "socratic_hint": "Посмотри на знаки при x = 0",
  "thought_forks": [
    "Знак минус (-)",
    "Знак плюс (+)",
    "Нельзя определить"
  ]
}
Когда requires_fork: false, фронтенд просто прячет блок развилок и разблокирует поле ввода, возвращая ученика к самостоятельному решению.  
MD
